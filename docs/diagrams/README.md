# Diagrams

One diagram per `jev_judge.py` subcommand and per workflow that uses them.
Tree diagrams under `trees/` are generated by `scripts/gen_tree_diagrams.py`
from the shipped tree files; a test fails when they disagree.

| What | Diagram | When to use it |
| --- | --- | --- |
| `quality` | [quality.md](quality.md) | Is a REQ, NFR or ADR well written? One run. |
| Quality trees | [trees/quality-req.md](trees/quality-req.md), [trees/quality-nfr.md](trees/quality-nfr.md), [trees/quality-adr.md](trees/quality-adr.md) | What Jev is asked and how answers become a verdict. |
| Diagnostic trees | [trees/diag-req.md](trees/diag-req.md), [trees/diag-nfr.md](trees/diag-nfr.md), [trees/diag-adr.md](trees/diag-adr.md) | Why a gate answer is weak. Never gates. |
| Gate (`jev_gate.py`) | [gate.md](gate.md) | Does a record pass over three runs? |
| `drift` | [drift.md](drift.md) | Does a rewrite still require what the original did? |
| `compare-definition` | [compare.md](compare.md) | Does adding a definition change Jev's answers? |
| `batch` | [batch.md](batch.md) | Low layer: raw request lines in, result lines out. |
| `validate` | [validate.md](validate.md) | Check one input file offline. |
| `doctor` | [doctor.md](doctor.md) | Check every tree, question set and definitions file offline. |
| Definitions | [definitions.md](definitions.md) | How definitions reach a request. |
| Fix workflow | [fix.md](fix.md) | Fix one record that fails the gate. |
| Write workflow | [write.md](write.md) | Rewrite a record from its tenets. |
| `check`, `check --profile` | [check.md](check.md), [check-profile.md](check-profile.md) | Planned (compliance); not in this release. |
